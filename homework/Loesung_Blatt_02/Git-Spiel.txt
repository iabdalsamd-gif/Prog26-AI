Git-Spiel
Betrachten Sie erneut die Vorgaben zur "Git-Quest". Die Geschichte des Helden Markus findet im master-Branch kein Ende, sondern erst im Hilfsbranch end.

Machen Sie nun verschiedene Experimente mit Branches in Git, und starten Sie dabei jeweils mit einem frischen Klon der Vorgaben.

1.Ändern Sie eine Datei, die im Branch end nicht verändert wurde. Erzeugen Sie mit diesen Änderungen auf dem master einen neuen Commit. Mergen Sie danach den Branch end in den master-Branch.
- git clone clone https://github.com/Programmiermethoden-CampusMinden/prog2_ybel_gitquest.git | Repo geklont 
- git diff master..end --name-onle |Dateien anzeigen mit Änderungen zwischen master und end damit ich diese für den nächsten schritt nicht ändern 
- nano hero.md | +Hero Markus
- git add hero.md | in Staging Area packen
- git commit -m "Add name Markus to hero.md" | committen. 
- git merge end | Integration von end zu Master 

2.Ändern Sie nun eine Datei, die auch im Branch end verändert wurde. Achten Sie dabei darauf, die Änderung an einer anderen Stelle in der Datei vorzunehmen. Erzeugen Sie mit diesen Änderungen auf dem master einen neuen Commit. Mergen Sie danach den Branch end in den master-Branch.
-neu geklont
-von Aufgabe 1 weiß man noch das stats auch in end geändert würde. 
- nano stats.md |+ ein Änderung
- git add stats.md
- git commit -m "Modified: stats.md"
- git merge end | den vorgeschlagene commit massage übernommen "Merge branch 'end'"  


3.Wie (2), aber ändern Sie nun eine Stelle, die auch im Branch end verändert wurde. Erzeugen Sie mit diesen Änderungen auf dem master einen neuen Commit. Mergen Sie danach den Branch end in den master-Branch. Was passiert, wenn die Änderung im master identisch zu der in end ist? Was passiert, wenn die Änderung im master anders ist als in end?
-Neuer Clone 
- nano stats.md | zu Waffen ein Pistole hin gefügt mit 20 dmg 
- git add . | alles was modified oder untrackt zu Staging Area packen
- git commit -m "Modified: stats.md"
- git merge end | Ausgabe: Merge conflict in stats.md
| Property   | Value         |
|------------|---------------|
<<<<<<< HEAD
| health     | 8             |
| experience | 40            |
| hunger     | 0             |
| weapons    | sword (3 dmg) |
|            | pistol (20dmg)|
=======
| health     | 2             |
| experience | 300           |
| hunger     | 10            |
| weapon     | sword (3 dmg) |
>>>>>>> origin/end
| armor      | light (2 dmg) |
|            |               |

-Die Änderungen die in master identisch sind werden einfach gemergt (kommen nur einmal vor)
-aber alles andere führt zu ein Merge conflict : der geänderte Inhalt von beiden seiten werde das Document geschrieben. 
-der Inhalt in Master und in End werden separate geschrieben in der selbe Document geschrieben. So muss man händisch das was man nicht brauch löschen.     
4.Wie (2), aber setzen Sie bitte den Branch end auf die Spitze von master, bevor Sie end in master mergen.
-Neuen Clone 
- nano stats.md |+neue Änderungen
- git add .
- git commit -m "Modified: stats.md"
- git switch end | Auf end Branch gewechselt 
- git rebase master |end auf der Spitze von master setzten 
- git switch master | auf master branch wechseln
- git merge origin/end | master mit end mergen

Was beobachten Sie jeweils? Erklären Sie Ihre Beobachtungen. Wenn es Konflikte gibt: Wie lösen Sie diese auf? Demonstrieren Sie das Vorgehen im Praktikum live.
